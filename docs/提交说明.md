# 论证工坊 ArguMentor — 参赛说明

**它是什么。** 一个本机运行、零依赖的网页应用，为中国高校英语专业学生提供英语论证写作教练。四个 DeepSeek 智能体分工给出反馈；学生回答它们的追问，对每条建议作出决定，并亲自改写。教师设计任务，并能看到全班的学习过程。

**类别。** 教育类智能体 · 二语写作 · 带程序化诚信层的多智能体系统

---

## 它要解决的问题

AI 写作反馈有一个在演示中很难看出的失效模式：**学生读完了，什么也没有改变**。作者此前的研究发现，仅仅*阅读* AI 生成的论证辩论的英语学习者，其写作质量并不优于阅读普通正反方材料的学习者。**接触不等于参与。**

实际部署的工具还普遍存在三个问题：

1. **反馈无处落点。** “你的推理联系可以更清楚”指向不了任何具体文字；而对 B1 水平的读者来说，一句虚构的引文与真实引文看起来完全一样。
2. **悄悄代写。** 工具一旦说“这是更好的版本”，文章就是它写的。系统提示里的政策声明阻止不了这件事，只有代码可以。
3. **闭环缺失。** 修订稿没人读，学生和教师都不知道建议到底有没有被采纳。

---

## 这个智能体的不同之处

### 1. 学生必须回答

第 3 步是对话，不是报告。苏格拉底式追问角色依据分析角色识别出的**论证类型**（举例、权威、因果、后果、类比、数据、价值、实践推理——每类都有自己的关键问题，参照 Walton、Reed 与 Macagno 的论证型式）提出 2–3 个问题。学生用英语回答，教练可以深入追问、聚焦追问、确认发现或小结，最多三轮——**但绝不代答**。

在录制的演示中，学生最初写的是 *“Employers should not use AI systems to monitor their employees”*。三轮之后，他自己写下：

> “Maybe the real problem is using AI scores without a human check, not monitoring itself.”

这句话是学生的，系统只是不断追问。随后它成为了学生修订后的主张。

### 2. 诚信层是代码，不是承诺

每条模型输出在显示给学生之前都要通过 `guard.mjs`：

- 对“学生原话”的引用**逐词定位**，核对不上即隐藏并记录；
- 学生文本中不存在的文献、URL、DOI、年份、百分比与统计数字，一律判为虚构；
- 可直接粘贴的改写句，以及与学生句子高度重合的长句，判为代写；
- 诱导性、复合、祈使伪装的问句一律拒绝；
- 句子框架限制固定词数，与学生文本有 4-gram 重合即删除。

出现违规会触发一次**能看到学生原文**的修复调用；若仍失败，则**只删除违规条目**，保留其余可用反馈。空回复会重新生成，而不会被“修复”成凭空捏造的内容。学生可以展开守门日志，查看本轮核对情况、实际服务的模型与提示词版本。

真实评测结果：**引用核实率 100%，立场评价性措辞 0 处，种子缺陷与注入预期 12/12 达成。**

### 3. 闭环，且学生始终是决策者

每条修订重点都必须作出决定——**采纳、调整、不采纳，或“还没看懂”**——拒绝也要写明理由。改写之后，修订检查将每条重点标为**已体现／部分体现／尚未体现／学生决定不采纳**，只描述“读者现在能看到什么”，**不打分**。下一轮反馈会收到上一轮的决定，因此被拒绝的建议不会被反复劝说，而“还没看懂”是一个正式选项，而不是沉默的不采纳。

### 4. 立场中立是被检验的，不是被声称的

评测脚本运行**立场翻转对**：同样的论证弱点，相反的立场。两对的分析诊断一致率为 100% 与 75%，两侧反馈篇幅接近，评价性措辞均为 0。剩余的不一致可追溯到两份草稿措辞上的真实差异。

## 对教师

任务设计器（议题、读者、结构要求、关注标准、本周语言重点、AI 使用规则、议题词汇、最多 6 份材料）导出 JSON 文件供学生载入。学生引用这些材料时，引文会被逐词核对——于是“核查来源”从一句建议变成了一项确定性检查。

全班概览导入学生导出的记录，显示追问回答数、决定分布、修订检查结果，以及全班的追问与学生发现，并可导出 CSV。全部在浏览器内完成，不上传任何数据。

## 工程实现

- **零依赖。** Node ≥ 20.3，约 5,000 行。`npm start` 就是全部部署。
- **60 项自动化测试**，全部离线运行。
- **API 密钥存放在项目文件夹之外**，因此压缩或分享文件夹不会泄露密钥。打包脚本在发现疑似密钥时会拒绝打包。
- **每轮都有溯源信息**：运行 ID、请求模型与实际服务模型、提示词版本哈希、模式、解码参数、调用与 token 数、修复次数、同意书版本，全部写入导出记录。之所以如此，是因为作者此前遇到过提供方别名在研究进行中被静默重映射到新模型版本。
- **课堂模式**：可配置绑定地址、课堂访问码、带位置提示的 FIFO 排队、重启后仍然有效的每日调用与 token 上限。
- **无障碍与隐私**：重绘时保持焦点与滚动位置，错误直接指向出错字段，发送前检测个人信息并支持一键遮蔽，公用电脑模式在关闭浏览器后清除记录。

## 诚实的局限

- **目前没有学习成效证据。** 现有测量都是关于智能体行为的，不是关于学生是否进步。下一步需要带对照组的课堂研究。
- **多智能体架构在现有证据下尚未证明其成本合理。** 单次调用的消融条件在缺陷检出上与四次调用的流程持平，而 token 仅为 47%。`REVIEW_MODE` 让这保持为一个实证问题，而不是设计假设；角色划分目前可辩护的贡献，是为守门与逐条采纳追踪提供了清晰的职责分离。
- **守门是句法层面的**，彻底改写的代写可能漏过，偶尔也会误删合法表达（误删均有记录）。
- **单一提供方、单一模型。** 四个角色之间的一致**不是**独立验证——它们共用同一个模型。

## 两分钟上手

```bash
npm run start:offline     # 无需密钥；反馈来自明确标注的固定模板
```
然后打开 `http://localhost:4186/?demo=1` 查看**录制演示**：一次完整的两轮会话，议题为“雇主是否应被允许用 AI 监控员工工作”，其中智能体的输出全部录制自真实 DeepSeek 运行，并带有解说面板逐步说明。

有密钥时：`npm run setup` → `npm run check`（免费） → `npm start`。
