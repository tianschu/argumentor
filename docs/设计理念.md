# 设计理念

论证工坊 v4 每个部件为何如此设计、依据什么证据、哪些仍未得到检验。

---

## 一、核心约束：参与，而非接触

作者此前的两阶段研究得出三个结论，直接塑造了这一设计：

1. **阅读** AI 生成论证辩论的学习者，其写作并不优于阅读普通正反方材料的学习者。阅读 AI 输出本身不构成干预。
2. 给 LLM 辩手设定**人设**对输出质量没有可靠影响（|d| ≤ .16）。
3. 真正的多智能体辩论**并未**超过强单智能体基线；思维链条件得分最高。

设计后果是直接的。结论 1 意味着学生必须对反馈**做点什么**，因此工具的核心是一场必须回答的对话，以及对每条建议必须作出的决定。结论 2 和 3 意味着四智能体划分不能靠断言来辩护，因此角色按**功能与信息**而非人设标签定义，并以 `REVIEW_MODE` 把架构保留为一个实证问题（见第五节）。

---

## 二、论证模型

论证地图采用 Toulmin 式结构，保留对英语专业论证教学真正重要的部件：

- **主张 + 限定。** 过度断言是新手论证写作最常见的弱点。给限定单独一个字段，使“范围”成为可见、可编辑的对象，而不是事后补充。
- **理由 → 证据 → 证据类型 → 来源 → 推理联系。** **证据类型**选择器（已收集／教师材料／个人经历／计划中／假设）迫使学生标注证据的认识论地位。这也正是分析角色得以区分“字段填满了”与“理由有支撑”的依据——上一版本无法作出这一区分。
- **双层推理联系。** 提示词明确要求分别检查*证据→理由*与*理由→主张*，因为学生完全可能写出成立的证据链接，而理由本身与主张无关。分析角色分别报告这两层。
- **带针对目标与回应策略的异议。** 异议可针对主张或某条具体理由，学生需选择反驳／让步／权衡／限定。“只见己方”是新手书面论证中最稳固的弱点；把回应*策略*显式化，使“加一条异议”变成一个推理选择。分析角色会检查让步是否反映在主张的范围中——这是最有价值的一处张力。

**论证型式。** 分析角色为每条理由标注型式（举例、权威、因果、后果、类比、数据、价值、实践推理），苏格拉底角色据此从该型式的**关键问题**库中取材（改写自 Walton、Reed 与 Macagno《Argumentation Schemes》，2008）。这正是防止追问滑向“你考虑过其他角度吗”这类万能句式的机制——不同的推理有不同的击破方式，而学生也因此把“问题类型”学成一种可复用的工具。

## 三、对话

苏格拉底式教学要求学生先给出答案，教师再就该答案追问。四条设计规则：

- **动作是有类型的**：深入追问、聚焦追问、确认发现、解释反馈、小结。“聚焦追问”专为回避问题的回答而设——没有它，含糊的回答只会换来一句客气的跟进，学不到东西。
- **三轮上限**，随后强制小结，并**用学生自己的话**概括其所得（引用的“发现”与其他引用一样，需在学生回复中核实）。
- **教练绝不代答。** 学生要求它替自己决定时，它会说明决定权在学生，并把问题收窄。
- **“这条什么意思？”** 可对任意一条反馈开启澄清线程。对 B1 学生而言，瓶颈往往是看不懂反馈，而不是论证本身。`clarify` 动作用更浅白的话解释术语，指向学生自己的文字，并仍以一个问题收尾。

学生在对话中产生的发现会被带到修订台，使改写从**学生自己的结论**出发，而不是从 AI 的建议出发。

## 四、诚信守门

系统提示里的政策是一个请求，守门是一道执行层。它作用于每一条输出。

**锚定。** 每条反馈必须引用学生文本中 3–25 个连续词。守门对双方分词，忽略大小写与标点匹配词序，并**用学生的原始片段替换模型给出的引文**。核对不上的引用会被丢弃并记录，而不是显示——锚定错误是本流程中最严重的失效，因为其余角色都建立在分析角色的输出之上，而共用同一模型的角色之间的一致看起来却像是相互印证。

**封闭世界检查。** URL、DOI、作者—年份引用、“et al.”、四位年份、百分比与带量词的统计数字，都必须出现在学生自己的文本中，否则一律判为虚构。这很严格，而且是刻意如此：英语学习者完全可能把一条看起来可信的引用直接粘进文章。

**代写检测。** 三道检测：显式措辞（“here is a revised version”“your claim could be:”）；并非学生原话的长引号句；以及与学生文本 4-gram 重合度 ≥50% 的 ≥14 词无引号句。最后一条用于捕捉“不声明的改写”这一常见规避方式。该近似复制检测在**对话与修订检查角色中被关闭**——在那里，把学生自己的话复述回去恰恰是它的职责。

**追问形式。** 必须且只能有一个问号；不得使用诱导句式（“Don't you think…”），不得使用伪装成问题的祈使句（“Why don't you add…”）。诱导性问题直接把结论交了出去，抹掉了对话存在的那一步推理。

**句子框架。** 固定词数上限 14、槽位 1–3，与学生文本有任何 4-gram 重合即删除。没有这条，“框架”可以把学生自己的句子连同填好的槽一起还给他——这是代写的侧门。

**失败处理。** 硬性违规触发一次**能看到学生原文**的修复调用；若再次失败，`salvage()` 只删除违规条目，保留仍然可用的一轮。**空回复或被截断的回复会重新生成，而非修复**——对着空内容做“修复”会凭空捏造反馈，这正是上一版本中真实发生过的失效。模型拒答时直接失败并明确说明：这不是对学生论证的评价。

## 五、架构，以及它为何保持可证伪

```
论证分析 ──→ 苏格拉底追问 ┐
   │          （型式关键问题）├──→ 修订协调 ──→ 诚信守门 ──→ 学生
   └───────→ 语言教练 ──────┘
```

角色按**信息与功能**而非人设区分：

| 角色 | 能看到 | 产出 | 不做 |
|---|---|---|---|
| 论证分析 | 地图、初稿、材料、引文核对结果、学生自评、历史轮次；**看不到支持等级** | 结构化检查、型式标注、1–3 条带锚定的观察、一条“值得保留” | 提问 |
| 苏格拉底追问 | 分析交接 + 型式关键问题 | 2–3 个带类型与锚定的问题 | 诊断、给事实 |
| 语言教练 | 学生自己的句子 + 确定性语言信号 | 1–2 条锚定的立场／衔接／来源表述／用词精确说明，可选框架 | 改语法、改写 |
| 修订协调 | 各角色条目及其 ID | 1–2 条带 `basedOn` 引用与自查问题的重点 | 提出新问题 |

两处刻意选择：

- **分析角色对等级不可见。** B1/B2/C1 只改变反馈的*措辞*与支架数量，绝不改变诊断。让分析角色在结构上根本看不到等级，意味着这一点由构造保证，而非寄望于模型遵守。
- **修订协调只能挑选，不能发明。** 其 `basedOn` 引用会与已知条目 ID 比对，无效引用被剥离并记录。协调角色失败时，修订重点由程序从分析结果确定性汇总，并在界面上明确标注。

**支架消退。** 从第 2 轮起默认关闭句子框架（B1 保留，其他等级可主动索取）。从第 3 轮起，追问角色邀请学生自拟一个关键问题。历史轮次的重点、决定与修订检查状态会向前传递，因此已解决的问题不再重提，被拒绝的建议也不再劝说。

**消融实验是内置的。** `REVIEW_MODE=single` 用一次调用产出同样四部分输出，并经过同一道守门；`multi-nocoord` 则去掉协调角色。当前评测（见 `评测报告.md` 第四节）显示：单次调用在缺陷检出上与四次调用的流程持平，而 token 仅为 47%。这一结果被如实报告而非隐藏，因为作者自己先前的发现正预测了它——而且一个无法被证伪的架构不构成贡献。

## 六、这一工具所支持的研究

以下研究均无需新的课堂数据采集，可在合成或公开语料上运行。

**研究一 — 角色划分是否值回成本？**
条件：单次调用；开启推理的单次调用；四角色流程；去掉协调角色；去掉交接；并将功能式角色与人设式角色与上述条件交叉。材料：把现有样例扩展至约 60 份论证地图，取自公开学习者语料（ICNALE、PELIC）与 Stab 和 Gurevych 的标注议论文语料。结果指标：种子缺陷检出、引用核实率、守门违规率、政策违规率、token 成本。分析：带条目随机效应的混合模型，并加入 TOST 等价检验——需要被击败的假设正是*无差异*。采集前预注册；`REVIEW_MODE` 开关与溯源记录均已就位。

**研究二 — LLM 反馈的测量不变性。**
同等论证质量，是否在不同母语背景、水平层级、议题与文本长度下获得同样的诊断？立场翻转设计可直接推广：固定论证结构，变动某一表层属性。结果指标：结构化分析检查上的一致率。这是任何已部署评估类智能体都需回答的公平性问题。

**研究三 — 漂移与金丝雀集。**
每轮都记录溯源信息（请求模型、实际服务模型、提示词版本哈希、参数、日期），正是因为作者此前遇到过提供方别名在研究中途被静默重映射。固定的金丝雀样例集定期重跑，可把漂移从看不见的混淆变量变成可测量的量。

**研究四 — 提示词注入与政策违规率。**
目前这一例注入样例只是冒烟测试。一套完整的红队语料（在每个学生字段中注入、经由修复路径洗白、跨角色传播）可给出按角色与攻击类型划分的攻击成功率，并可比较多智能体与单次调用条件下的放大效应。

**上述四项所需的仪表已经就位：** 每轮运行 ID、实际服务模型捕获、提示词版本哈希、守门日志、修复与重生成计数、条目级 ID、带理由的逐条学生决定、修订检查状态，以及带校验码的导出。

## 七、刻意不做的事

- **不打分、不评级、不推断水平。** 修订检查描述的是可见变化。打分会把形成性工具变成评估工具，并恰好招来本设计意在避免的过度依赖。
- **不使用 AI 文本检测器。** 它们不可靠，且对二语写作者存在偏见。工具转而为学生提供一处结构化的 AI 使用说明，并依据其自身过程记录草拟。
- **不做检索。** 提示词明确告知智能体无法核查事实，只能说明需要哪种核查，而不能给出答案。教师提供的材料是唯一可核查的证据，其引文由代码逐词核实。
- **无云端账户、无遥测。** 全部本机运行；记录留在学生浏览器中，直到他们自己导出。
