## 一、这是什么，以及它拒绝做什么

论证工坊是一个**本机运行、零依赖**的网页应用，为高校英语专业学生提供英语论证写作教练。四个 DeepSeek 智能体给出反馈；学生回答它们的追问，对每条建议作出决定，并亲自改写文本。

**它拒绝：**

| 它不会 | 原因 |
|---|---|
| 替学生写或改写句子 | 学生的作者身份是核心；这一点由代码强制，而非靠提示词请求 |
| 给出分数、等级或水平判断 | 打分会把形成性反馈变成评估，并招致过度依赖 |
| 提供事实、数据、文献或链接 | 它没有检索能力；任何"引用"都会是捏造的 |
| 判断议题哪一方正确 | 两种立场适用同样的标准、同样的严格度，且这一点经过检验 |
| 使用 AI 文本检测器 | 它们不可靠，且对二语写作者存在偏见 |

如果你需要的是一个批改作文的工具，这不是它。

## 二、设计理念

### 塑造它的那个发现

在一项两阶段研究中，**阅读** AI 生成论证辩论的学习者，其论证写作**并不优于**阅读普通正反方材料的学习者。同一研究计划的另外两个结果：给 LLM 辩手设定**人设**对输出质量没有可靠影响（|d| ≤ .16）；真正的多智能体辩论**并未**超过强单智能体基线。

结论是：**接触 AI 的推理不构成干预；参与或许可以。**

因此，本工具的核心不是反馈本身，而是学生被要求**行动**的三个位置：

```
        AI 产出                            学生必须行动
  ┌────────────────────────┐     ┌──────────────────────────────┐
  │ 诊断 + 追问            │ ──▶ │ 1. 回答追问                  │  ← 多轮，无法跳过
  │ 修订重点               │ ──▶ │ 2. 对每条作出决定            │  ← 采纳/调整/不采纳/还没看懂
  │ 对变化的描述           │ ──▶ │ 3. 亲自改写                  │  ← 编辑器只属于学生
  └────────────────────────┘     └──────────────────────────────┘
```

### 四项设计承诺

**1. 一切都锚定在学生自己的文字上。**
每条观察与追问都必须引用学生所写的 3–25 个连续词。引文由代码逐词核实，并在显示前**替换为学生的原始片段**。无法核实的引文会被隐藏。泛泛的教师腔（"你的推理联系可以更清楚"）无法通过这一关。

**2. 政策是代码，不是提示词里的承诺。**
系统提示里写"不要代写文章"只是一个请求。`guard.mjs` 是一道执行层，作用于每一条输出，并且可以删除模型已经产生的内容。

**3. 学生可以说不。**
拒绝建议是一项正式操作，需要写明理由。"还没看懂"是第四个选项——因为未被察觉的不理解，是最常见也最难看见的不采纳形式。被拒绝的建议在后续轮次不会被再次提出。

**4. 架构必须可证伪。**
鉴于上述第 2 个发现，四智能体划分不能靠断言来辩护。`REVIEW_MODE` 可以把同样的工作改为一次调用、或去掉协调角色，使这个问题保持实证性。当前诚实的答案见第九节——它并不美化这个架构。

## 三、安装与运行

**要求：** Node.js 20.3 或以上。无需 `npm install`——没有任何依赖。

### 三种使用方式

| 模式 | 命令 | 需要密钥？ | 反馈来自 |
|---|---|---|---|
| **演示** | 打开站点，或本机 `?demo=1` | 否 | 真实录制的 DeepSeek 会话，只读回放 |
| **离线** | `npm run start:offline` | 否 | 固定模板，界面明确标注——用于熟悉流程 |
| **实时** | `npm run setup` 后 `npm start` | 是 | 真实 AI 反馈 |

### 首次实时运行

```bash
npm run setup     # 询问模型与 API 密钥；密钥不会回显
npm run check     # 免费验证——列出账户可用模型，不消耗 token
npm start         # 然后打开 http://localhost:4186
```

macOS 可双击 `启动论证工坊.command`；Windows 双击 `启动论证工坊.bat`。

### 密钥保存位置

| 系统 | 位置 |
|---|---|
| macOS / Linux | `~/.config/argumentor/env` |
| Windows | `%APPDATA%\ArguMentor\env` |

**刻意放在项目文件夹之外**——因此压缩、复制或分享该文件夹都不会泄露密钥。若发现旧版遗留在文件夹内的 `.env`，服务启动时会提示，`npm run setup` 可一键迁移。打包脚本在发现疑似密钥时会拒绝打包。

### 成本

一次完整反馈是 **4 次模型调用**；每条对话回复 1 次；每次修订检查 1 次。一次典型的两轮会话（含对话）约 19 次调用。在 `deepseek-flash` 上金额很小，但这是**你的**钱：前几次使用请关注 DeepSeek 用量页面。

## 四、五步流程详解

### 第 1 步 · 明确任务

设定**议题**、**目标读者**、**核心主张**与**主张限定**。

限定不是装饰。过度断言是新手论证写作最常见的弱点，给范围单独一个字段，使它成为可编辑的对象而非事后补充。"雇主绝不应监控员工"与"雇主不应用 AI 为个人生产效率打分并据此评判，除非有人复核每个分数"是两个不同的论证，而只有后者能被两个案例支撑。

**支持等级**（B1/B2/C1）只改变反馈的*措辞*与语言支架的数量，绝不改变诊断——分析角色根本看不到它（见第六节）。

### 第 2 步 · 构建论证

每条理由是一个单元：

```
理由 ─── 证据 ─── 证据类型 ─── 来源
  │              （已收集／教师材料／个人经历／
  │                计划中／假设）
  └─── 推理联系：两层链接
           证据 → 理由  （"这为什么能证明理由成立？"）
           理由 → 主张  （"这位读者为什么应当因此接受主张？"）
```

**证据类型**选择器迫使学生如实标注证据的认识论地位，这也正是分析角色得以区分"字段填满了"与"理由有支撑"的依据。

**异议**可针对主张或某条具体理由，并需选择**回应策略**：反驳、让步、权衡、限定。这把"加一条异议"变成一个推理选择。分析角色会检查让步是否反映在主张的范围中——这是最有价值的一处张力。

**加引号的引文会被核实。** 若你用引号引用教师提供的材料，工具会逐词核对这些词是否真的出现在该材料中——完全不调用模型：

> ✗ 引文未在材料中找到 S1 —— "flagged workers who helped their colleagues as lazy"

这能在请求任何反馈之前，抓出凭记忆误引的引文。

### 第 3 步 · 追问对话

**先自评。** 运行之前，学生先指出自己认为最薄弱的部分，并用一句英语说明原因。分析角色会先回应这个判断——"你正确地指出理由 2 缺少推理联系，这确实是最重要的问题"，或者"这是真实存在的，但另一个问题更优先，因为……"。这是在练习评价性判断，而不是替代它。

然后流程运行（约 7 秒，4 次调用）：

```
论证分析 ──→ 苏格拉底追问 ┐
   (A)     ╲ （型式关键问题）├──→ 修订协调 (R) ──→ 诚信守门 ──→ 学生
            ╲→ 语言教练 (L)┘
```

然后**学生回答追问**。整个工具就是为这一步而存在的。见第五节。

### 第 4 步 · 自主修订

一屏之内：左侧是修订重点与你在对话中的发现，右侧是编辑器。

每条重点都需要一个**决定**——采纳／调整／不采纳／还没看懂——以及一行理由。"从我的初稿开始修改"会把被审阅的初稿复制进编辑器；"显示修改对比"给出词级差异。AI 绝不在这个框里写字。

### 第 5 步 · 检查反思

**修订检查**逐条描述读者现在能看到什么：

| 状态 | 含义 |
|---|---|
| 已体现 | 修订明确处理了该重点，并引用你新文本中的原话 |
| 部分体现 | 有相关改动，但仍有缺口，并指出缺什么 |
| 尚未体现 | 这条重点在文本中没有可见的改动 |
| 学生决定不采纳 | 你拒绝了它；系统记录这一选择的后果，而不与你争辩 |

随后是：下一次可迁移的**策略**（下个任务开始时会提醒你）、由你确认的 **AI 使用说明**（根据你自己的过程记录草拟），以及**导出**（HTML 或 JSON，带 SHA-256 校验码）。

## 五、如何与智能体对话

这是大多数人最初会用错的部分，因为它的行为不像聊天机器人。

### 对话规则

- 每个问题**最多回答 3 次**。之后教练会小结你自己得出的结论并结束该线程。
- 教练**绝不会回答自己提出的问题**。如果你要它替你决定，它会说决定权在你，并问一个更窄的问题。
- 回复必须用**英语**，且不能只有一两个词。（括号里的简短中文夹注在任何地方都可以——"the 996 schedule（996工作制）"可以通过。）
- `Ctrl/⌘ + Enter` 发送。

### 教练如何处理你的回复

| 动作 | 何时 | 表现为 |
|---|---|---|
| **深入追问** | 回复切题 | 再深一层：证据、假设、范围、后果 |
| **聚焦追问** | 回复回避问题、重复自己或含糊 | 友善地点出缺口，并问一个更窄的版本 |
| **确认发现** | 回复包含真正的洞见 | 引用你的原话，并问这会如何改变你的主张 |
| **解释反馈** | 仅用于"这条什么意思？"线程 | 用更浅白的话解释，然后仍以一个问题收尾 |
| **小结** | 第 3 轮，或你已解决 | 概括**你的**结论，并建议带入修订 |

### 有效的回复

> "I think the manager would need to know how often the system makes this mistake. In Case A it happened in
> the first month, but I don't know if it continued after the company changed the rule."

具体、承认不确定、正面处理问题。教练可以就此深入。

> "Hmm, after the fix a supervisor checks the score before any action, so one wrong flag would not punish a
> worker directly. Maybe the real problem is using AI scores without a human check, not monitoring itself."

这就是一个有产出的回合该有的样子：学生在句子中途改变了自己的想法。这句来自录制演示的真实回复，后来成了该学生修订后的主张。

### 浪费一个回合的回复

| 回复 | 会发生什么 |
|---|---|
| "Yes." / "I agree." | 聚焦追问。没有可深入的内容。 |
| "What should I write?" | 教练说决定权在你，并把问题收窄。一个回合没了。 |
| "Can you give me an example?" | 它没有检索能力，也不会编造。 |
| 改写自己的句子并问"这样更好吗？" | 它不能替你评价改写，只会问**你**认为改变了什么。 |

### 看不懂某条反馈时

点击任意条目下的**"这条什么意思？"**。这会开启一条独立线程，教练用更浅白的话解释术语、指向你自己的文字，并以一个问题收尾。来自演示：

> **学生：** "I am not sure what a hedge is here. Do you mean that I should not give my opinion so strongly?"
>
> **教练：** "A hedge means softening a claim to fit your evidence. Your word 'totally' says AI is always
> unfair, but Case A is only one example. Hedging is not hiding your opinion; it keeps it believable. Which
> part of Reason 2 could you soften to match one example?"

使用这个功能不是失败。它会被记录为参与，而"还没看懂"本身就是一个有效的决定。

### 写好自评

点出**具体的**要素与**具体的**疑虑。

- ✓ "I did not explain why one mistake in Case A means AI monitoring is unfair in general."
- ✓ "I am not sure the board will accept that two designers leaving a studio is a cost for a logistics company."
- ✗ "My essay is not good enough." —— 分析角色无从确认或细化。

### 跨轮次

第 2 轮不是重新开始。流程会收到上一轮的重点、你的决定与理由，以及修订检查的状态。因此：

- 被标为**已体现**的问题不会再提。
- 你**带理由拒绝**的建议不会被再次劝说。如果你的理由显示出误解，你可能会收到一个关于它的问题。
- 从第 2 轮起，**句子框架默认关闭**（B1 保留，其他等级可勾选索取）。从第 3 轮起，系统邀请你自拟一个关键问题。支架是有意消退的。

## 六、四个智能体各自做什么

角色按**功能与信息**区分，而非人设。（上文的人设零效应正是原因。）

### 论证分析 (A) —— 只诊断，从不提问

在任何散文之前先产出结构化诊断标签：

```json
{ "claim":  { "scope": "overbroad", "answersTopic": "yes" },
  "reasons": [{ "target": "Reason 1", "evidenceStatus": "source",
                "evidenceLink": "partly", "claimLink": "missing" }],
  "counterarguments": [{ "target": "Counterargument 1",
                         "fairness": "fair", "responseType": "rebut" }] }
```

这些标签驱动你看到的那张表，也正是大规模评测得以可能的基础（第九节）。它还会引用你的原话，指出一处**值得保留**。

**它看不到你的支持等级。** 诊断与等级无关这一点由构造保证，而非寄望于模型遵守。

### 苏格拉底追问 (S) —— 只提问，从不诊断

接收分析角色的交接，外加分析角色所识别**论证型式**对应的**关键问题**（举例、权威、因果、后果、类比、数据、价值、实践推理——参照 Walton、Reed 与 Macagno）。不同的推理有不同的击破方式，因此真正能驳倒你这条理由的问题，取决于它的类型。

每个问题都有类型：澄清概念、检验假设、追问证据、其他解释、推演后果、对方视角、读者视角、**前后对照**、自拟追问。其中 `前后对照` 把你**自己的**两句话并排放在一起——这是一个没有检索能力的工具所能使用的最强招法，因为它不需要任何外部事实。

问题的形式也会被校验：必须且只能有一个问号，不得使用诱导句式（"Don't you think…"），不得使用伪装成问题的祈使句（"Why don't you add…"）。诱导性问题直接把结论交了出去。

### 语言教练 (L) —— 指向你的句子，不做普遍的语法纠正

只处理四个标准：**立场强度**（缓和语／强化语是否与证据相符）、**逻辑衔接**、**来源表述**、**用词精确**。确定性的词表信号先由代码算出，作为提示交给教练，而教练必须对照你的文本逐一核实。

句子框架限制在 14 个固定词、1–3 个槽位，并且**与你的文本有任何 4-gram 重合即删除**——否则"框架"可能把你自己的句子连同填好的槽一起还给你。

### 修订协调 (R) —— 只挑选，从不发明

从其他角色的条目中选出 1–2 条重点，并在 `basedOn` 中标明来源条目 ID。无效引用会被剥离。每条重点都带一个**自查问题**——你可以用它检验自己的修订。它会指出各角色之间的张力而不是掩盖。若它失败，修订重点由程序从分析结果确定性汇总，并在界面上标注"程序汇总"。

## 七、诚信守门

每条输出在学生看到之前都要通过 `guard.mjs`。

| 检查 | 命中时 |
|---|---|
| 对你原话的引用 | 逐词定位；无法核实则隐藏并记录 |
| 你文本中没有的 URL、DOI、作者—年份引用、年份、百分比、统计数字 | 判为虚构 → 修复调用 |
| 可直接粘贴的改写句；与你句子高度重合的长句（4-gram 重合 ≥50%） | 判为代写 → 修复调用 |
| 诱导性、复合、祈使伪装的问句 | 拒绝 → 修复调用 |
| 不安全的句子框架 | 删除 |
| 非英语输出 | 除非引用你的原文，否则判为违规 |

**失败处理。** 硬性违规触发**一次**能看到你原文的修复调用；若再次失败，只删除违规条目，保留本轮其余内容。**空回复或被截断的回复会重新生成，而非修复**——对着空内容做"修复"会凭空捏造反馈，这正是版本 3 中真实发生过的失效。模型拒答时直接失败，并明确说明这不是对你论证的评价。

展开反馈底部的**"诚信守门与运行记录"**，可查看本轮核对情况、实际服务的模型、提示词版本与 token 数。

## 八、给教师

### 设计任务

**教师**页面 → **任务设计**。你可以设定议题与读者（可锁定）、结构要求、字数范围、本次关注的论证标准、本周语言重点、AI 使用规则、议题词汇，以及最多 6 份材料。导出 JSON 发给学生，学生在第 1 步载入。

**材料包是价值最高的字段。** 因为学生引用你材料中的原文会被代码逐词核实，"核查来源"从一句建议变成了一项确定性检查。请写简短、真实的案例，并注明材料性质——示例任务使用两份教师编写的虚构案例，并明确说明了这一点。

设计材料时请让**双方都能被有力地论证**。示例材料包中刻意既有监控减少了事故的案例，也有监控导致员工流失的案例。

### 读懂全班

**教师**页面 → **全班概览** → 导入学生导出的 JSON。你会看到追问回答数、决定分布、修订检查结果、全班的追问与学生发现（可用于课堂讨论），以及 CSV 导出。全部在浏览器内完成，不上传任何数据。

**这些数字意味着什么，以及不意味着什么。**

- **追问回答数**是参与度最好的单一指标。
- **决定**体现推理：一条带充分理由的*不采纳*，比四次被动采纳是更好的作业。
- **"还没看懂"**是教学信号，不是失败。多名学生在同一条上标注它，就是一节小课的内容。
- **粘贴**只记录*次数与字符数，绝不记录内容*。它不能证明文本来源。请把它当作对话的由头，绝不可当作证据。
- **校验码不一致**说明文件在导出后被修改过。它能发现随意的编辑，发现不了刻意的篡改。

### 课堂用法

三种行之有效的安排：

1. **课前：** 学生在家完成论证地图并运行第 1 轮。你阅读全班的苏格拉底式追问，用其中反复出现的两三个问题开启课堂。
2. **课中：** 学生两人一组回答追问，先争论答案再输入。对话是人际讨论的引子，不是替代品。
3. **课后：** 学生完成修订、运行检查、写下迁移策略。你阅读过程记录，而不只是最终文本。

在任务中设置**最少回答的追问数**（默认 1，示例任务用 2）。学生试图跳过时工具会提示，并记录这一跳过。

## 九、给研究者

### 每轮的溯源信息

每轮都记录：运行 ID、**请求的模型与实际服务的模型**、提示词版本哈希、模式、解码参数、调用／token／修复次数、守门日志、同意书版本——全部写入导出文件。之所以如此，是因为曾观察到提供方别名在研究进行中被静默重映射到新模型版本。

### 内置评测

```bash
npm run eval:offline   # 流程自检，不调用 API
npm run eval           # 真实评测，约 24 次调用
npm run eval -- --mode single          # 单次调用消融
npm run eval -- --rescore <file.json>  # 从已保存的运行离线重算指标
```

测量：守门拦截、引用核实率、**立场翻转对称性**（同样的弱点、相反的立场）、提示词注入抵抗、种子缺陷检出、token 与耗时。

### 诚实报告的消融结果

`REVIEW_MODE` = `multi` | `multi-nocoord` | `single`。在当前样例集上，**单次调用在缺陷检出上与四次调用的流程持平，而 token 仅为 47%。** 流程被测到的优势更窄：引用核实无一遗漏、无不安全框架、跨立场的标准选择更稳定。

基于这一证据，四次调用尚未被输出质量所证成。角色划分当下可辩护的贡献是**职责分离**——每个角色拥有各自的条目 ID，因而决定与采纳情况可以逐条记录，守门也能针对角色施加不同规则。这一点写在提交文档里而非被掩盖，因为一个无法被证伪的架构不构成贡献。

### 该工具支持的四项研究（均无需新的课堂数据）

1. **角色划分是否值回成本？** 将各条件与"功能式／人设式角色"交叉，在约 60 份论证地图上运行，地图取自公开学习者语料（ICNALE、PELIC）与 Stab 和 Gurevych 的标注议论文语料。混合模型加 TOST 等价检验——需要被击败的假设正是*无差异*。
2. **测量不变性。** 同等论证质量，是否在不同母语背景、水平、议题与长度下获得同样的诊断？立场翻转设计可直接推广。
3. **漂移与金丝雀集。** 溯源记录加上定期重跑的固定样例集，可把静默的模型漂移变成可测量的量。
4. **提示词注入与政策违规率。** 目前这一例注入样例只是冒烟测试；完整的红队语料可给出按角色与攻击类型划分的攻击成功率。

## 十一、隐私、成本与课堂部署

- 学习记录**只存在于学生浏览器中**。支持导出、清空与**公用电脑模式**（关闭浏览器即清除）。
- 任何运行之前必须勾选**版本化的数据说明**；同意书版本会写入导出文件。
- 发送前运行**个人信息筛查**：邮箱、手机号、证件号、长数字串，并支持一键遮蔽。跨轮次携带的文本（收获、决定理由、目标）同样纳入筛查。
- **不使用 AI 文本检测器。** AI 使用说明由过程记录草拟、学生确认。
- **课堂局域网：** 设置 `HOST`、`ALLOWED_HOSTS` 与 `ACCESS_CODE`。服务端有带位置提示的 FIFO 排队，以及重启后仍有效的每日调用与 token 上限。详见 `.env.example`。
- **托管：** 部署 `worker/`。**切勿把密钥放进静态页面**——DeepSeek 没有按密钥的消费上限，密钥一旦暴露，损失的是整个预付余额。

## 十二、常见问题

| 现象 | 原因与处理 |
|---|---|
| "DeepSeek 尚未配置" | 运行 `npm run setup` 后重启。可用 `npm run check` 免费验证。 |
| "当前模型名称不可用" | `npm run check` 会列出账户可用模型；重新运行 setup 并选择其一。 |
| "自上一轮以来论证没有变化" | 这是设计使然——先根据反馈修改，再请求新一轮。 |
| "这里需要用英语写作" | 括号中的简短中文夹注可以；中文句子不行。"来源"字段接受中文题名。 |
| "检测到可能的个人信息" | 删除它或点击"自动遮蔽"。在清理干净之前，文本不会被发送。 |
| "模型输出未通过诚信与格式检查" | 守门删除了不安全内容且无法挽救出可用的一轮。请重新运行。 |
| "模型拒绝讨论这一议题" | 这是提供方的拒答，不是对你论证的评价。可与教师商量换一种表述。 |
| 端口 4186 被占用 | 修改配置文件中的 `PORT`。 |
| 提示项目文件夹内有 `.env` | 这是旧版密钥位置。运行 `npm run setup` 迁移。 |

## 十三、诚实的局限

- **目前没有学习成效证据。** 现有测量都是关于智能体行为的，不是关于学生是否进步。那需要带对照组的课堂研究。
- **多智能体架构在现有证据下尚未证明其成本合理**（第九节）。
- **守门是句法层面的。** 它匹配的是模式与词序，不是语义。彻底改写的代写可能通过，偶尔也会误删合法表达（误删均有记录）。
- **单一提供方、单一模型。** 四个角色之间的一致**不是**独立验证——它们共用同一个模型。
- **修订检查描述的是文本中可见的变化**，不是论证质量。
- **面向单一机构的设计假设。** 它是为中国高校英语专业学生而建；英语夹注规则与双语界面都反映了这一点。
